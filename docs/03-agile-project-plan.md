# Agile Project Plan

## 1. Methodology

The project synopsis specifies the Scrum framework. Work is divided into short sprints, each with a defined goal, backlog items, review, and retrospective.

The team roles described in the synopsis are:

- **Product Owner:** Defines project requirements, prioritizes backlog items, validates features, and represents end-user needs.
- **Scrum Master:** Coordinates Scrum activities, tracks sprint progress, removes blockers, and supports the team's Agile process.
- **Algorithm / Backend Developer:** Designs graph representation, conflict detection, timetable algorithms, APIs, and core backend logic.
- **Frontend / Database & QA Developer:** Develops the user interface, database integration, input/output screens, testing, and documentation.

## 3. Initial Product Backlog

| ID | User Story | Priority |
|---|---|---|
| US01 | As an administrator, I want to add students, courses, rooms, and examination details so that the system has complete input data. | High |
| US02 | As an administrator, I want the system to identify examination conflicts automatically so that clashes are avoided. | High |
| US03 | As an administrator, I want to generate an examination timetable automatically so that scheduling effort is reduced. | High |
| US04 | As an administrator, I want rooms to be assigned according to capacity so that students are seated appropriately. | High |
| US05 | As an administrator, I want a seating plan for each examination session so that students can be placed systematically. | High |
| US06 | As an administrator, I want to regenerate the schedule when constraints change so that updated plans can be produced. | Medium |
| US07 | As an administrator, I want to view and export the final timetable and seating plan so that they can be shared with students and staff. | Medium |

## 4. Definition of a Completed Sprint Item

A backlog item can be considered complete when:

- The planned functionality has been implemented.
- The relevant logic has been tested with suitable sample data.
- The output has been checked against the requirement.
- Any identified issue has been recorded for follow-up.
- The team has reviewed the increment.

These are proposed working checks for the project; the synopsis does not provide a formal Definition of Done.

## 5. Sprint Review and Retrospective

At the end of each sprint, the team should:

1. Demonstrate the completed increment.
2. Compare the delivered work with the sprint goal.
3. Record defects or incomplete work.
4. Discuss blockers and improvements.
5. Update and reprioritize the product backlog where necessary.

## 6. Final Deliverables

- Working prototype for examination data input.
- Examination conflict graph.
- Timetable generated using graph-coloring algorithms.
- Room allocation and seating-plan generation.
- Graph and timetable visualization.
- Exportable seating-plan PDF.
- Project report and final demonstration.
