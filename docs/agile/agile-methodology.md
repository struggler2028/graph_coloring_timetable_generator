# Agile Methodology & Development Framework

## 1. Overview
The **Dynamic Graph Coloring Based Exam Timetabling and Seating Plan Generator** project follows the **Scrum Agile Framework** augmented with **Extreme Programming (XP)** engineering practices. This hybrid methodology ensures rapid iteration, mathematically sound algorithm verification, and transparent delivery of increments.

## 2. Scrum Pillars & Core Values
The team adheres to the three empirical Scrum pillars:
- **Transparency:** All artifacts, algorithms, graph models, and conflict detection logs are documented and visible to all stakeholders.
- **Inspection:** Progress is evaluated against sprint goals, algorithmic correctness (zero-clash schedules), and capacity constraints at regular cadence.
- **Adaptation:** As course structures, student enrollments, or room capacities change, the timetabling logic and backlog items are adjusted immediately.

## 3. Team Roles & Responsibilities
| Role | Primary Responsibility | Focus Areas |
|---|---|---|
| **Product Owner** | Backlog prioritization, requirement validation | Examination conflict policies, academic constraint definition |
| **Scrum Master** | Sprint facilitation, impediment removal | Agile ceremony adherence, velocity tracking, blocker resolution |
| **Algorithm & Backend Developer** | Core algorithmic engine, graph data structures | Greedy Coloring, DSATUR algorithm, FastAPI endpoints, room allocation |
| **Frontend & QA Developer** | User experience, visualization, verification | Cytoscape.js network visualizer, schedule grid, test automation |

## 4. Sprint Cadence & Timeboxing
Development is executed across **4 distinct sprints** (1 week each):
- **Sprint 1:** Requirement Analysis, Mathematical Formulations, Architecture & Data Modeling.
- **Sprint 2:** Graph Construction, Conflict Edge Detection & Timetable Coloring (Greedy & DSATUR).
- **Sprint 3:** Room Allocation Algorithm, Seating Plan Matrix & Backend API Integration.
- **Sprint 4:** Interactive Visualizer, Cytoscape Integration, End-to-End Testing & PDF Export.

## 5. Artifacts Maintained
1. **Product Backlog:** Prioritized list of all user stories and technical tasks.
2. **Sprint Backlogs:** Targeted commitments for each sprint with task breakdowns.
3. **Sprint Reviews & Retrospectives:** Post-sprint evaluation and continuous improvement actions.
4. **Traceability Matrix:** Bidirectional mapping from functional requirements to test cases.
