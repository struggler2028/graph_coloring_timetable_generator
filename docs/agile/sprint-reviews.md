# Sprint Reviews & Increment Demonstrations

## 1. Overview
The Sprint Review is held at the conclusion of each sprint to inspect the completed increment, demonstrate working software to stakeholders, and adapt the Product Backlog based on feedback.

---

## 2. Sprint 1 Review
- **Increment Demonstrated:** Pydantic data schemas, conflict graph mathematical model, and modular architecture specification.
- **Stakeholder Feedback:** The data models are clean and comprehensive. Stakeholders requested that rooms include building names for better physical navigation.
- **Outcome:** Accepted as meeting Sprint 1 Definition of Done.

---

## 3. Sprint 2 Review
- **Increment Demonstrated:** Working graph builder, Greedy Coloring, and DSATUR algorithm with verification tests showing zero conflicts.
- **Stakeholder Feedback:** Impressed with the comparative metrics showing DSATUR's ability to save time slots on dense graphs.
- **Outcome:** Accepted as meeting Sprint 2 Definition of Done.

---

## 4. Sprint 3 Review
- **Increment Demonstrated:** Room allocation and seating plan generation integrated with FastAPI REST endpoints.
- **Stakeholder Feedback:** Seating coordinates (`R01-S01`) are very practical for examination proctors and invigilators.
- **Outcome:** Accepted as meeting Sprint 3 Definition of Done.

---

## 5. Sprint 4 Review
- **Increment Demonstrated:** Complete full-stack web application featuring interactive Cytoscape network graph, algorithm comparison dashboard, schedule grid, room seating visualizer, and PDF export.
- **Stakeholder Feedback:** Exceeds expectations. The visualization makes conflict inspection intuitive and the export report is ready for production use.
- **Final Outcome:** Final prototype accepted for deployment and academic evaluation.
