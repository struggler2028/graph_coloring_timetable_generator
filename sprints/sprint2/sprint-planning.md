# Sprint 2 – Sprint Planning

## 1. Sprint Overview

- **Project:** Dynamic Graph Coloring Based Exam Timetabling and Seating Plan Generator
- **Sprint:** Sprint 2 – Graph and Timetable Generation
- **Duration:** Week 2
- **Methodology:** Agile Scrum
- **Sprint Status:** Planned

## 2. Sprint Goal

The primary goal of Sprint 2 is to develop the examination conflict graph and implement graph-coloring algorithms to generate a timetable without clashes between examinations sharing students.

## 3. Sprint Objectives

- Implement the examination conflict graph.
- Represent examinations as graph vertices.
- Identify conflicts using shared-student information.
- Establish edges between conflicting examinations.
- Implement Greedy Coloring.
- Implement DSATUR-based scheduling.
- Generate examination time-slot allocations.
- Compare the results of both algorithms.

## 4. Sprint Scope

The following features are included:

1. Graph representation of examinations.
2. Examination conflict detection.
3. Adjacency list implementation.
4. Greedy Coloring algorithm.
5. DSATUR algorithm.
6. Timetable generation.
7. Comparison of algorithm results.

Room allocation, seating-plan generation, and PDF export are excluded from this sprint.

## 5. Team Responsibilities

Team members will collaborate on graph construction, conflict detection, algorithm implementation, testing, and documentation.

Individual task ownership and contributions will be recorded in the sprint backlog.

## 6. Expected Deliverables

- Examination conflict graph.
- Shared-student conflict detection.
- Working Greedy Coloring implementation.
- Working DSATUR implementation.
- Generated examination timetable.
- Algorithm comparison results.
- Testing documentation.

## 7. Definition of Done

A task will be considered complete when:

- The required algorithm or functionality is implemented.
- Relevant test cases are executed.
- Generated results are checked for correctness.
- Code is integrated into the project.
- Documentation is updated.
- Supporting evidence is recorded.

## 8. Sprint Outcome

The actual sprint outcome and completion status will be recorded after implementation, testing, and sprint review.
