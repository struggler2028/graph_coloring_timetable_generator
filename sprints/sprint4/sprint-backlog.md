# Sprint 4 – Sprint Backlog

## Sprint Goal
To complete frontend and backend integration, test the complete system, and prepare the final project demonstration.

## User Stories and Tasks

### S4-01: Frontend and Backend Integration
**Priority:** High  
**Story Points:** 5

Tasks:
- Connect frontend screens with backend services.
- Connect student, course, examination, and room data.
- Display generated timetables and seating plans.
- Handle user inputs and system responses.

Acceptance Criteria:
- Frontend communicates correctly with backend modules.
- Data is displayed properly.
- Errors are handled appropriately.

### S4-02: Complete System Testing
**Priority:** High  
**Story Points:** 5

Tasks:
- Test the complete examination scheduling workflow.
- Test Greedy and DSATUR algorithms.
- Validate examination conflicts.
- Test room allocation and seating plans.
- Test schedule regeneration after input changes.

Acceptance Criteria:
- No conflicting examinations are assigned the same time slot.
- Room capacities are respected.
- Every registered student receives a valid seat.
- Changes in input data can be handled correctly.

### S4-03: Optimization and Report Generation
**Priority:** Medium  
**Story Points:** 3

Tasks:
- Test the system with different dataset sizes.
- Identify and improve performance issues.
- Generate timetable reports.
- Generate seating plan reports in PDF format.

Acceptance Criteria:
- System produces valid outputs for test datasets.
- Performance observations are documented.
- Reports contain correct timetable and seating information.

### S4-04: Final Documentation and Demonstration
**Priority:** High  
**Story Points:** 3

Tasks:
- Prepare final project documentation.
- Add screenshots of implemented features.
- Prepare the project presentation.
- Demonstrate the complete system workflow.

Acceptance Criteria:
- Documentation covers all major modules.
- Screenshots show actual system outputs.
- Final demonstration explains the complete workflow.
