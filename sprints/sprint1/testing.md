# Sprint 1 – Testing and Validation

## 1. Testing Objective

The objective of Sprint 1 testing is to review the correctness and completeness of the initial project requirements, database design, and user interface wireframes.

## 2. Planned Test Cases

| Test ID | Test Scenario | Expected Result |
|---|---|---|
| TC-01 | Review functional requirements | All main system functions are identified. |
| TC-02 | Review non-functional requirements | Quality expectations are documented. |
| TC-03 | Check student entity design | Required student attributes are identified. |
| TC-04 | Check course entity design | Course information is represented correctly. |
| TC-05 | Check examination entity design | Examination details are identified. |
| TC-06 | Check room entity design | Room capacity information is included. |
| TC-07 | Review entity relationships | Required database relationships are defined. |
| TC-08 | Review administrator dashboard wireframe | Main dashboard sections are included. |
| TC-09 | Review input screen wireframes | Required data-entry screens are planned. |
| TC-10 | Review output screen wireframes | Timetable and seating-plan sections are included. |

## 3. Testing Approach

Testing and validation will be performed using:

- Requirement review.
- Database design verification.
- Entity relationship checking.
- UI wireframe review.
- Team review and feedback.

## 4. Testing Results

Actual results and pass/fail status will be recorded after the review.

| Test ID | Actual Result | Status |
|---|---|---|
| TC-01 to TC-10 | Pending review | Not Tested |

## 5. Defect Tracking

Any missing requirements, incorrect database relationships, or incomplete wireframes will be documented and corrected.

## 6. Conclusion

Sprint 1 validation will ensure that the initial requirements, database design, and interface planning are ready for the development activities in the next sprint.
